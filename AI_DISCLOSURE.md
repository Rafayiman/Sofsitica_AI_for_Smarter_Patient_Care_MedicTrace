# AI Disclosure

Required transparency statement (per the challenge brief, Safety and responsible AI). Every item below is also enforced in the
code, not just documented.

## 1. Models used

| Model | Provider | Used for |
|---|---|---|
| Llama 3.3 70B (`llama-3.3-70b-versatile`) | Groq API | (a) generating SELECT-only SQL from natural-language questions; (b) summarizing the rows the validated query actually returned |
| None | — | **Never** used for diagnosis, treatment recommendations, or any clinical interpretation output |

The summarizer is prompted to describe only what the rows show, to begin with an
`[AI-generated summary]` tag, and to never invent values. The SQL step is constrained by a
validator (`app/llm/sql_guard.py`) that is applied to every generated query before execution.

## 2. External services

- Groq API only (LLM inference). No other external service is called by the backend or frontend.

## 3. External reference data

- MIMIC-IV Clinical Database Demo v2.2 — the source dataset (PhysioNet). See `references.md`
  for the full citation. All event values, timestamps, and identifiers come from these files.
- No ICD code description dictionaries or other external lookup tables were used; labels are
  taken directly from the demo dataset files (e.g. `d_labitems`, drug names in `prescriptions`).

## 4. Test data

- The 24-question evaluation set in `eval/questions.json` is hand-authored for this project
  (every question is labeled `[SYNTHETIC]` in the file and in `EVAL.md`) and is kept
  separate from the dataset itself. Every expected answer in it was hand-verified against
  the source rows before being recorded. The dataset rows themselves are real MIMIC-IV
  Demo v2.2 rows, not synthetic.

## 5. Manually authored data-quality rules (every threshold documented in code)

| rule_id | Threshold source (see `backend/app/ingest/quality_rules.py` for constants) | Severity |
|---|---|---|
| `missing_value` | Structural: rows that require a value/timestamp for their event type | — |
| `duplicate` | Exact equality on patient/type/subtype/timestamp/value | — |
| `implausible_range` | Standard adult reference ranges, hardcoded per subtype (creatinine, potassium, sodium, hemoglobin, WBC, platelets, heart rate, systolic/diastolic BP, SpO₂, temperature) with a code comment citing the range convention | — |
| `temporal_misalignment` | Admission/discharge windows from the source admissions/icustays data; single source of truth `TEMPORAL_TOLERANCE = "120"` minutes (event must fall >2 h outside its ICU or admission window) | minor ≤12 h, moderate 12–24 h, severe >24 h |
| `chronology_violation` | Structural, no tolerance: ICU stay outtime < intime, discharge time < admission time | severe |
| `bp_relationship_invalid` | Same-reading pair: systolic < diastolic in one (patient, encounter, timestamp, source) NIBP/ABP reading | severe |

All thresholds are hardcoded constants in `backend/app/ingest/quality_rules.py`; no rule
or threshold was generated by an LLM.

## 7. Limitations (explicitly stated)

- This sample (n = 100, single center) cannot establish generalizability, clinical validity,
  or accuracy claims beyond this dataset. A correct finding here is simply that the tool
  works as designed on a small sample.
- Dates are shifted by the dataset; timestamps are only comparable within one patient.
- The demo is research/descriptive only and is not for clinical decision-making.
- Quality flags are heuristic, additive, and never modify or delete source rows.

## 8. Human review boundary

- The eval set's expected answers and the quality-rule seeded labels were **hand-authored
  and hand-verified** against the source rows (see `EVAL.md`); the prose-to-citation
  mapping was spot-checked by hand. No metric, number, or threshold in the docs was
  produced by an LLM. LLM output is confined to (a) SQL generation (validated before
  execution) and (b) answer summarization, both clearly tagged in the UI (`[AI-generated
  summary]`) and non-executive — the summaries are descriptive, never prescriptive.

## 9. Data minimization

- The LLM is exposed only to (a) the `events`/`raw_*` table schema (table + column names)
  and (b) at most **30 rows × 120 characters** of de-identified event values per
  summarization window; the SQL generator never receives raw patient content. This demo
  subset contains no PHI (dates are shifted by the dataset; IDs are re-mapped); the same
  minimization applies regardless.

## 10. Subgroup consideration

- No subgroup analysis is performed or claimed: the demo subset is n = 100, single
  center, and the UI exposes one patient at a time. No statement in this project asserts
  equal performance across demographic groups, and none should be inferred from a sample
  of this size.
